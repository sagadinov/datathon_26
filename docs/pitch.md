# План питча (5 минут)

1. **Проблема (30 с).** Кассовая зона: наличные без присмотра, открытый сейф, посторонние у кассы,
   уход без закрытия. Контроль по записям вручную — часы просмотра; нужен локальный сервис,
   который сам находит момент и показывает кадр.

2. **Демо (90 с).** Веб-интерфейс: загрузить ролик → вердикт, список нарушений с таймкодом, описанием
   по видимым признакам, 1–3 кадрами с рамками и пунктом Правил НБРК № 231. Тот же результат через
   `POST /api/v1/analyze` + `GET /api/v1/jobs/{id}` с `X-API-Key`. Показать X-20 (открытый сейф, 5 с)
   и X-26 (пачка на столе, кассир ушёл).

3. **Метрики на 42 роликах (45 с).** Recall 0.82 (18/22), ложных 1/20, таймкод ±5 с в 0.89 случаев,
   2 с на ролик с кэшем, холодный ролик 143 с — 93 с через публичный URL (бюджет 170 с).
   Устойчивость: зеркальные и уменьшенные копии — ложных 1–2/20.

4. **Архитектура (60 с).** Всё локально, CPU: ffmpeg 2 fps → Grounding DINO tiny (Apache-2.0, текстовые
   запросы вместо обучения) → трекер людей → авто-зоны сцены (стол, место кассира, сейф, дверь —
   без пиксельных констант, другой ракурс работает автоматически) → таймлайн состояния → правила
   T1–T10 с порогами в секундах и относительными порогами → сравнение с фоном стола для пачки
   12–25 px, которую не видит детектор. Лица не распознаются, облачных API нет, видео жюри не хранятся.

5. **Ограничения и что дальше (45 с).** Не ловим «деньги в руках под столом» (T7) — нужна поза рук;
   эксперимент с RTMPose дал 1 из 4 и в сервис не включён. Пропуски на зеркальном ракурсе — логика
   стороны сцены. Дальше: поза рук, VLM-подтверждение на GPU, обучение на размеченных событиях банка.

Ответы на вероятные вопросы: лицензии (Apache-2.0, ultralytics отклонён как AGPL), почему без
обучения (42 ролика — только правила и проверка), как считали метрики (`eval/evaluate.py`, разметка
из таблицы кейса), что будет на другом ракурсе (зоны из детекций, прогон на hflip).
