## 1. Что мы делаем (суть ТЗ)

Сервис принимает видео (.mov, ~29 МБ, 10–145 с, без звука, одна камера, одна касса),
анализирует его **полностью локально** и возвращает:

- вердикт `violation` / `no_violation` на всё видео;
- список нарушений: `type`, `timecode_sec`, `description`, `evidence_frames` (1–3 JPEG base64);
- для каждого типа — ссылку на правило и нормативный источник РК (НБРК, adilet.zan.kz).

Нужны: веб-интерфейс (загрузка → статус → результат) **и** публичный API для жюри.

### Жёсткие запреты (дисквалификация)
- Любые облачные AI-API (OpenAI, Gemini, Claude, облачные OCR/vision) при обработке видео,
  в т.ч. передача им кадров или описаний. Все модели — локально, веса скачаны заранее.
- Распознавание и идентификация лиц. Людей детектируем как «person», не как личность.
- Готовые решения. Open-source модели и библиотеки с коммерческой лицензией — можно.
- Тестовые видео жюри нельзя сохранять для обучения/публиковать.

### Критерии (100 баллов) — что оптимизируем
| Критерий | Баллы | Как считается |
|---|---|---|
| Обнаружение (вердикт на видео) | 25 | автоматически по JSON |
| Локализация (таймкод + кадр) | 15 | автоматически по JSON |
| Классификация (тип) | 15 | автоматически по JSON |
| Обоснованность правил (нормативка без выдумок) | 15 | вручную |
| Устойчивость (новые видео, другой ракурс) | 10 | тест: 5+ видео, финальное под другим углом |
| Готовность продукта (UI, надёжность) | 10 | вручную |
| Техническое решение (архитектура, локальность) | 10 | вручную |

Пропуск нарушения хуже ложного срабатывания, но «нарушение» без обоснования штрафуется.
Описание — только то, что видно, без предположений («деньги лежат на столе, кассир вне
кадра 12 с») — не «кассир украл».

## 2. API (точно по ТЗ, не отклоняться)

Заголовок `X-API-Key: <ключ>` обязателен; без него/с неверным — 401.

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/v1/analyze` | multipart, поле `file` (.mov). Ответ: `{"job_id": "..."}` |
| GET | `/api/v1/jobs/{job_id}` | `status`: `processing` / `done` / `failed` + результат |

Формат результата при `done`:
```json
{
  "job_id": "3f2a9c1e",
  "status": "done",
  "verdict": "violation",
  "violations": [
    {
      "type": "Наличные без присмотра",
      "timecode_sec": 44.2,
      "description": "Что видно на видео и почему это может быть нарушением",
      "evidence_frames": [
        { "timestamp_sec": 44.2, "image_base64": "/9j/4AAQ..." }
      ]
    }
  ]
}
```
`verdict` ∈ {`no_violation`, `violation`}; `violations` пустой при `no_violation`.
Поля `rule`/`source` в схеме ТЗ нет — добавляем их **дополнительными** полями в каждое
нарушение (`"rule": {...}`), не ломая обязательные. UI их показывает.

Примеры запросов для проверки:
```bash
curl -X POST $URL/api/v1/analyze -H "X-API-Key: $KEY" -F "file=@data/open/videos/X-1.mov"
curl $URL/api/v1/jobs/<job_id> -H "X-API-Key: $KEY"
```

## 3. Датасет

`data/open/videos/*.mov` — 42 ролика (имена `X-N.mov`, в части имён кириллическая «Х»
закодирована как `#U0425-N.mov` — матчить по номеру N, не по префиксу).
`data/open/open_labels.xlsx` — лист `labels`: `наименование файла` | `таймстемп`
(«22 секунда», «1минута 8 секунда», пусто) | `нарушение / без нарушения`.

- 22 ролика с нарушением, 20 без. Один таймкод на ролик = **начало** события.
- Вертикальное видео 464×848, 30 fps, 12–143 с. Камера — верхний угол комнаты, снято
  телефоном. В датасете уже **два разных положения стола/камеры**.
- Сцена: стол кассира, счётная машинка, ноутбук (экран виден), телефон, сейф (серый шкаф
  справа от стола), стеклянная дверь слева. Два разных кассира (розовая кофта / белая
  блузка) — не различать, оба «cashier».
- Тип нарушения в разметке **не указан** — ниже наша реконструкция по просмотру кадров.

### Типы нарушений (наша типология) и ролики
| id | type (строка в JSON) | Что видно | Ролики, t |
|---|---|---|---|
| T1 | Наличные/ценности без присмотра | деньги или инкассаторская сумка на столе, кассир отошёл / уже сел следующий клиент | X-4 57, X-26 9, X-38 33, X-15 15 |
| T2 | Уход с рабочего места без закрытия | кассир вышел из кассы, ноутбук включён с открытой системой | X-28 7, X-22 14, X-11 18 |
| T3 | Открытый сейф | дверца сейфа осталась открытой, кассир занялся другим | X-20 5 |
| T4 | Посторонний в кассовой зоне | второй человек вошёл в помещение / за стол во время операции | X-18 20, X-30 13 |
| T5 | Личные вещи в кассовом помещении | кассир вошёл с сумкой, положил куртку/сумку на стол | X-32 5, X-33 6, X-40 17 |
| T6 | Посторонние предметы / напитки на рабочем месте | стакан кофе над наличными, журнал | X-46 11, X-47 68, X-24 8 |
| T7 | Наличные вне зоны видимости | купюры прижаты к телу, уходят под стол / в карман | X-1 22, X-44 16, X-13 47, X-2 10 |
| T8 | Пересчёт без клиента | клиент ушёл, кассир продолжает считать его деньги | X-34 13 |
| T9 | Нарушение при приёме инкассации | инкассатор оставил сумку и ушёл без передачи/проверки | X-17 7 |

Чистые ролики (X-3, 5, 8, 10, 12, 14, 16, 19, 21, 23, 25, 27, 29, 31, 35, 37, 39, 43, 45, 48):
обычное обслуживание, пересчёт на машинке, корректная приёмка сумки (инкассатор ждёт у стола),
закрытие сейфа → выключение света → выход (X-12 — это НОРМА, не нарушение).

**Выводы для правил:** «кассир вышел» само по себе не нарушение; нарушение — что осталось
(деньги на столе, включённый экран, открытый сейф). «Второй человек» — нарушение, только
если он в зоне кассира/за столом, а не у двери. В тесте могут быть типы, которых нет в
трейне — VLM-описание должно уметь выдавать «Иное: <что видно>».

## 4. Архитектура (решено, не переизобретать)

```
video.mov ─► ffmpeg (2 fps, resize до 640 по длинной стороне)
          ─► Детектор с открытым словарём (YOLO-World или Grounding DINO):
             person, cash/banknotes, bag, cup, jacket, laptop screen, safe door open, money bag
          ─► Трекинг людей (ByteTrack) + зоны: desk, cashier_side, safe, door  (зоны считаются
             автоматически от bbox стола/сейфа, НЕ хардкодить пиксели — ракурс в тесте другой)
          ─► Движок правил по состояниям во времени (T1–T9): события с t_start, t_end, score
          ─► VLM (Qwen2.5-VL-7B-Instruct, vLLM) ТОЛЬКО для кандидатов: окно ±3 с, 6–8 кадров,
             вопрос «подтверди/опровергни + опиши, что видно». Если GPU нет — пропускаем VLM,
             отдаём описание из шаблона правила (деградация, а не падение).
          ─► JSON по схеме + 1–3 кадра (JPEG q=80, ≤640 px)
```

- Бэкенд: FastAPI + фоновая очередь (один воркер, задания последовательно), SQLite/JSON
  для статусов, Docker. Фронт: Streamlit (или простой HTML), ходит в тот же API.
- Таймаут обработки одного видео — **180 с**, после него возвращаем лучший частичный результат
  (`done`), а не `failed`. Жюри ждёт 5 минут.
- Все веса — в `models/`, скачаны один раз; `OFFLINE=1` → никаких обращений в интернет
  при обработке (`HF_HUB_OFFLINE=1`, `TRANSFORMERS_OFFLINE=1`).
- Лицензии: YOLO-World (GPL/AGPL через ultralytics — **проверить**; если AGPL неприемлемо —
  Grounding DINO Apache-2.0 или RT-DETR), Qwen2.5-VL Apache-2.0, ByteTrack MIT.

## 5. Вычислительная среда (кластер) — ВАЖНО

- Слurm-кластер с fairshare. **Всего 12 GPU, очередь непредсказуемая.** CPU-ноды (zen4)
  почти всегда свободны.
- Поэтому: **всё, что можно, разрабатываем и тестируем на CPU.** Извлечение кадров, детектор
  (YOLO-World-S/M на CPU ~2–5 fps при 640 px — достаточно для 2 fps семплирования), трекинг,
  движок правил, API, фронт, оценочный скрипт — всё на CPU. GPU нужен только VLM и финальным
  прогонам.
- Пайплайн обязан иметь режим `--device cpu` и `--no-vlm`, которые дают валидный JSON.
  **Сервис для жюри должен отвечать даже без GPU** (детектор + правила на CPU, ≤180 с).
- Когда GPU получили — держать аллокацию, не отпускать: `salloc`/`sbatch` с длинным
  `--time`, внутри — vLLM-сервер, который живёт всё время. Проверить лимиты по времени
  `sinfo`/`sacctmgr show qos`. Если GPU дадут только на N часов — запланировать пере-запрос
  и CPU-fallback в API.
- Публичный URL: compute-ноды, скорее всего, не принимают входящие соединения. Варианты по
  убыванию предпочтения: (1) Cloudflare Tunnel (`cloudflared tunnel --url http://localhost:8000`)
  с ноды, где крутится API; (2) `ssh -R` реверс-туннель на внешний VPS/логин-ноду;
  (3) ngrok. Проверить **исходящий** доступ в интернет с compute-нод в первый час — если его
  нет, API хостим на логин-ноде/внешнем VPS, а GPU-нода работает как воркер через общую ФС
  (`/shared`) или ssh-туннель. Решить это до того, как писать фронт.
- Не ставить пакеты в системный Python; `python -m venv .venv` или conda в `/shared/home/...`.
  Кэш HF: `HF_HOME=/shared/home/sagyndyk.sagadinov/datathon/models/hf`.
- Полезно: `squeue -u $USER`, `sinfo -p <gpu partition>`, `nvidia-smi` внутри аллокации.

## 7. Оценочный скрипт — делать ПЕРВЫМ

`eval/evaluate.py` на всех 42 роликах считает:
- вердикт: accuracy, recall по violation (главное — recall ≈ 1.0), FP на чистых;
- таймкод: |t_pred − t_label| для TP, доля попаданий в ±3 с и ±5 с (у каждого ролика один
  метка-таймкод; если предсказано несколько событий — берём ближайшее);
- тип: наша метка T1–T9 из таблицы выше vs предсказанный (это прокси, разметки типов нет);
- время обработки на ролик (на CPU и на GPU отдельно).

Печатает таблицу по роликам + сводку, пишет `eval/results/<timestamp>_<git-sha>.json`.
Запускать после каждого значимого изменения правил/порогов. Не менять пороги «на глаз»
без прогона.

Проверка устойчивости: прогон на зеркальных (hflip) и слегка повёрнутых (±10°) копиях
роликов, плюс даунскейл до 360p — метрики не должны проседать.

## 8. Нормативная база (заполняется в `src/rules_catalog.py` и `docs/legal_sources.md`)

Только акты РК: постановления Правления Национального Банка РК о кассовых операциях и
инкассации в банках второго уровня, требования к кассовым узлам/помещениям; тексты — с
adilet.zan.kz. Правила: **ни одной ссылки без проверки по тексту документа**. Если точный
пункт не найден — писать документ без пункта (это допускается ТЗ), но не выдумывать номер.

## 9. Правила работы в репозитории

- Маленькие шаги, после каждого — `git commit`. Коммит-сообщения по-английски, коротко.
- Сначала план и список файлов, потом код. Никаких файлов >400 строк.
- Любая правка пайплайна → прогон `eval/evaluate.py` → метрики в сообщении о результате.
- Не трогать `data/`, не переименовывать видео. Не коммитить веса, видео, ключи.
- Логи — в `logs/`, уровень INFO, с таймингами каждого этапа на видео.
- Не использовать сетевые вызовы в коде обработки видео. Загрузка весов — только в
  `scripts/download_models.sh`.
- Если нужен GPU, а его нет — не ждать: делать CPU-часть и писать, что заблокировано.
- Язык UI и описаний — русский. Код, комментарии, коммиты — английский.
